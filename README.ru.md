<p align="center">Терминал, передача файлов, удалённый рабочий стол и повседневная эксплуатация — в единой рабочей среде.</p>

Qterm — настольный инструмент управления подключениями на **Go, Wails v3, Vue 3 и TypeScript** для macOS, Windows и Linux. Отправной точкой служит инвентарь хостов: подключение к серверам и устройствам в рабочей области с вкладками и разделёнными панелями, работа с файлами, мониторинг ресурсов, управление контейнерами и использование AI-ассистента из боковой панели инструментов.

Интерфейс доступен на семи языках: китайский (упрощённый), китайский (традиционный), английский, французский, японский, корейский и русский.

## Обзор возможностей

### Хосты и подключения

- **Единая библиотека ресурсов**: управление хостами и вложенными группами, поиск, метки, заметки, собственные значки и цвета, а также боковой и полноэкранный режимы инвентаря.
- **Разные способы подключения**: SSH, Telnet, последовательный порт, RDP, VNC и открытие локальной оболочки.
- **Аутентификация SSH**: пароль, закрытый ключ, SSH Agent, интерактивная аутентификация и настройка двухфакторной аутентификации с привязкой к записи OTP.
- **Сложный сетевой доступ**: цепочки промежуточных хостов SSH, прокси SOCKS5 / HTTP; конфигурации прокси можно использовать повторно, а для RDP и VNC также доступны промежуточный хост или цепочка прокси.
- **Параметры подключения**: настройка терминала, кодировки, keepalive, команды после входа, SFTP и удалённого рабочего стола для каждого протокола.

### Рабочая область терминала

- Вкладки нескольких сессий, блокировка и переименование вкладок, изменение порядка перетаскиванием, разделение на панели, а также отсоединение и присоединение окон сессий.
- Поиск в терминале, настраиваемая подсветка ключевых слов по регулярному выражению, история команд, автодополнение и сгруппированные быстрые команды.
- Настраиваемое подтверждение многострочной вставки, пакетные команды, поведение правой кнопки мыши, шрифт, курсор, буфер прокрутки и способ отрисовки.
- История и заметки сессий, запись терминала, воспроизведение и экспорт.
- Светлая / тёмная тема, цветовые схемы терминала, фоновое изображение и масштаб интерфейса.

### Файлы и эксплуатация

- **SFTP**: просмотр локальных и удалённых каталогов, отправка и скачивание, передача перетаскиванием, очередь передач, прогресс и отмена, подтверждение перезаписи и следование за каталогом.
- **Удалённое редактирование текста**: открытие удалённого файла во встроенном редакторе, сохранение после правок и обработка конфликтов изменения файла.
- **Проброс портов**: локальный, удалённый и динамический SOCKS-проброс с поддержкой групп и управлением состоянием.
- **Мониторинг ресурсов**: показатели CPU, памяти, дисков и сети с графиками за период; доступные показатели зависят от удалённой среды.
- **Процессы и службы**: просмотр процессов, управление службами в поддерживаемых системах и чтение журналов.
- **Docker**: управление удалёнными контейнерами, образами, томами и сетями через активную сессию SSH, просмотр сведений о ресурсах и журналов контейнеров.
- **Сеансы tmux**: список, создание и завершение сеансов tmux на удалённом хосте; «Подключиться» вводит `tmux attach` в текущий терминал, а сеансы переживают отключение.
- **Инструменты аутентификации**: управление записями TOTP / HOTP, импорт `otpauth://` или QR-кода, показ кодов, копирование и отображение QR-кода.

### AI-ассистент

Потоковый диалог в рабочей области: анализ задачи с учётом выбранного терминала, хоста и другого контекста, а также помощь инструментов Agent в выполнении задач.

- Настройка нескольких поставщиков моделей, адресов сервисов, моделей и ключей API с предварительной проверкой подключения.
- Поддержка протоколов OpenAI Chat Completions, OpenAI Responses и Anthropic Messages; конкретные возможности совместимого сервиса зависят от его реализации.
- История диалогов, отображение Markdown / кода / математических формул, утверждение команд и настройки поведения Agent.
- Команды Agent выполняются согласно локальной политике безопасности и настройкам утверждения; нативный вызов инструментов поддерживается в OpenAI Chat Completions и Anthropic, а в Responses используется совместимый резервный путь.

Перед использованием AI необходимо самостоятельно настроить сервис моделей. Содержимое, добавленное в контекст, отправляется настроенному сервису — выбирайте контекст с учётом реального объёма данных.

## Установка

Установочные пакеты публикуются в [GitHub Releases](https://github.com/LLiuHuan/Qterm/releases). Раскройте раздел **Assets** нужной версии и скачайте файл для своей операционной системы и архитектуры; архивы `Source code` содержат исходный код и не являются установщиками.

| Устройство                                           | Архитектура |
| ---------------------------------------------------- | ----------- |
| Mac на Apple Silicon (серия M)                       | `arm64`     |
| Mac на Intel                                         | `amd64`     |
| 64-битный компьютер Windows или Linux на Intel / AMD | `amd64`     |
| Компьютер Windows или устройство Linux на ARM64      | `arm64`     |

В Windows тип системы можно посмотреть в Параметры → Система → Сведения; в macOS — в разделе «Об этом Mac»; в Linux выполните `uname -m` (`x86_64` соответствует `amd64`, а `aarch64` — `arm64`). Пакеты для 32-битных систем не выпускаются.

### macOS

Требуется macOS 12 Monterey или новее.

**Установка через Homebrew**

Установите [Homebrew](https://brew.sh/), затем добавьте tap Qterm и установите приложение:

```sh
brew tap lliuhuan/tap
brew install --cask lliuhuan/tap/qterm
```

Homebrew автоматически выберет пакет arm64 или amd64 для вашего Mac. После установки откройте Qterm из папки «Программы» или выполните:

```sh
open /Applications/qterm.app
```

Обновление до новой версии:

```sh
brew update
brew upgrade --cask lliuhuan/tap/qterm
```

- Текущий пакет macOS использует ad-hoc подпись и не прошёл нотариальную проверку Apple. Если macOS заблокирует первый запуск, разрешите Qterm в «Системные настройки → Конфиденциальность и безопасность».
- Если Qterm был установлен вручную, Homebrew может сообщить, что приложение уже существует. Закройте Qterm и переместите существующий `/Applications/qterm.app` в другую папку через Finder, если хотите его сохранить, затем установите новую версию; удалять пользовательские данные Qterm не нужно.

**Ручная установка**

1. Скачайте `qterm-darwin-arm64.dmg` для Apple Silicon или `qterm-darwin-amd64.dmg` для Intel.
2. Откройте DMG и перетащите `qterm.app` в папку «Программы».
3. Запустите приложение из папки «Программы»; при появлении предупреждения следуйте инструкции о безопасности первого запуска выше.

Также можно скачать ZIP для нужной архитектуры, распаковать его и переместить `qterm.app` в «Программы». Для ручного обновления закройте Qterm и замените старое приложение новым.

### Windows

**Установщик**

1. Скачайте `qterm-windows-amd64-setup.exe`; на устройстве ARM64 выберите `qterm-windows-arm64-setup.exe`.
2. Запустите установщик и следуйте его шагам; при появлении запроса подтвердите права администратора.
3. Запустите Qterm из меню «Пуск» или с ярлыка на рабочем столе.

Qterm требует **Microsoft Edge WebView2 Runtime**. Установщик проверяет его наличие и пытается установить недостающий компонент. Если это не удалось или нужна установка без доступа к сети, скачайте Evergreen Standalone Installer с [официальной страницы Microsoft WebView2](https://developer.microsoft.com/en-us/microsoft-edge/webview2/), выберите x64 или ARM64, установите его и запустите Qterm.

**ZIP-пакет**

Скачайте `qterm-windows-amd64.zip` или `qterm-windows-arm64.zip`, полностью распакуйте архив в доступную для записи папку и запустите `qterm.exe`. ZIP-пакету также нужен WebView2 Runtime; не запускайте программу из окна предварительного просмотра архива.

Перед обновлением через установщик закройте Qterm. Для ZIP распакуйте новую версию и замените старую программу.

### Linux

Для Linux нужны графическая сессия и библиотеки выполнения GTK / WebKitGTK, соответствующие пакету. Текущие пакеты заявляют **GTK 4 и WebKitGTK 6.0**; старые дистрибутивы могут не предоставлять совместимые версии, поэтому совпадение архитектуры процессора само по себе не гарантирует совместимость.

Ниже используются имена для `amd64`; на ARM64 замените `amd64` на `arm64`. Сначала скачайте файл из Releases, затем выполните соответствующую команду в каталоге загрузок.

**Debian / Ubuntu: пакет DEB**

Скачайте `qterm-linux-amd64.deb` и установите его через APT, чтобы зависимости разрешились автоматически:

```sh
sudo apt update
sudo apt install ./qterm-linux-amd64.deb
```

Запустите приложение из меню или выполните `qterm` в терминале. Для обновления скачайте новый DEB и повторите ту же команду.

**Семейство Fedora / RHEL: пакет RPM**

На дистрибутиве, где доступны нужные библиотеки, скачайте `qterm-linux-amd64.rpm` и установите его:

```sh
sudo dnf install ./qterm-linux-amd64.rpm
```

Запустите приложение из меню или командой `qterm`. Для обновления выполните:

```sh
sudo dnf upgrade ./qterm-linux-amd64.rpm
```

Если менеджер пакетов сообщает о недостающих зависимостях, проверьте наличие нужных версий в репозиториях вашего дистрибутива; не устанавливайте пакет принудительно с игнорированием зависимостей. Совместимость со старыми версиями CentOS / RHEL не гарантируется.

**AppImage**

Скачайте `qterm-linux-amd64.AppImage`, добавьте право на выполнение и запустите:

```sh
chmod +x qterm-linux-amd64.AppImage
./qterm-linux-amd64.AppImage
```

Если отсутствует FUSE, установите требуемую вашей системой библиотеку FUSE или используйте пакет DEB / RPM. Совместимость AppImage с произвольно старыми дистрибутивами не гарантируется. Перед заменой файла новой версией закройте Qterm.

**Пакет tar.gz**

Скачайте `qterm-linux-amd64.tar.gz` и распакуйте его:

```sh
tar -xzf qterm-linux-amd64.tar.gz
chmod +x qterm
./qterm
```

Этот архив содержит только программу: системные библиотеки и пункт в меню приложений не устанавливаются. Для обновления закройте Qterm и замените распакованную программу новой версией.

## Начало работы

1. Запустите приложение и следуйте подсказкам, чтобы инициализировать или разблокировать локальное хранилище.
2. Создайте группы и хосты, выберите протокол и заполните параметры подключения; хосты также можно импортировать из существующего клиента.
3. Для хоста SSH настройте пароль, закрытый ключ или SSH Agent; при первом подключении проверьте и подтвердите отпечаток хоста.
4. Откройте сессию хоста и выберите нужные инструменты справа; для работы с AI сначала настройте сервис моделей в разделе «Настройки → AI-ассистент».
5. Настройте в параметрах внешний вид, терминал, сочетания клавиш, запись и параметры передачи файлов.

### Перенос конфигурации

Предусмотрен импорт из конфигурации OpenSSH, PuTTY, Xshell, Termius, SecureCRT, MobaXterm, WindTerm, FinalShell, Electerm и файлов сессий JSON, а также импорт и экспорт резервных копий ресурсов Qterm.

При импорте данные сначала сканируются и показываются в предварительном просмотре, после чего выбираются нужные записи. В зависимости от источника переносимые протоколы, учётные данные и дополнительные параметры различаются, поэтому результат нельзя считать полной копией конфигурации исходного клиента; для мастер-пароля или доступа к системным учётным данным может потребоваться дополнительный ввод.

### Локальные данные и учётные данные

Хосты, группы и история хранятся в локальной базе SQLite; секретные сведения находятся в зашифрованном хранилище. Хранилище использует AES-256-GCM, защита мастер-паролем основана на производной Argon2id, предусмотрены точки входа для смены ключа и пакета восстановления. При первом подключении SSH требуется подтвердить ключ хоста; доверенные отпечатки управляются в настройках.

## Локальная разработка

### Подготовка окружения

| Инструмент            | Текущая база проекта                                                                                                  |
| --------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Go                    | 1.26.0 или версия, совместимая с `go.mod`                                                                             |
| Node.js               | 22.x начиная с 22.22.2 или 24.x начиная с 24.15.0; должны выполняться требования engines зафиксированных зависимостей |
| npm                   | Установка зафиксированных зависимостей фронтенда                                                                      |
| Wails CLI             | v3.1.0, в соответствии с версией модуля Go                                                                            |
| Инструменты платформы | Для macOS нужны Xcode Command Line Tools; для других платформ — соответствующие нативные зависимости сборки           |

Команды выполняются в корне репозитория:

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
npm --prefix frontend ci
wails3 doctor
wails3 task dev
```

Убедитесь, что каталог исполняемых файлов Go добавлен в `PATH`. `wails3 task dev` использует `build/config.yml`, порт фронтенда по умолчанию — `9245`.

Предварительный просмотр только фронтенда (откройте `http://127.0.0.1:9245` в браузере; используется шлюз в памяти, без реальных возможностей SSH / SFTP):

```sh
npm --prefix frontend run dev
```

### Проверка и сборка

```sh
# Полная локальная проверка: формат Go, тесты, vet; формат, lint, типы, юнит-тесты, сборка и E2E фронтенда
wails3 task check

# Сборка приложения для текущей платформы
wails3 build

# Создание установочного / дистрибутивного пакета для текущей платформы
wails3 package
```

Полная проверка требует тестовых файлов в репозитории и окружения браузера Playwright; снимок кода без тестов не содержит полного набора проверок. При необходимости установите браузер для E2E:

```sh
cd frontend
npx playwright install chromium
```

### Портативные пакеты для шести платформ

Команды выполняются в корне репозитория под **macOS**:

```sh
# Только план
wails3 task release:all DRY_RUN=true

# Фактическая сборка
wails3 task release:all
```

Требуются Go, Node.js/npm, Wails CLI, Xcode Command Line Tools и запущенный Docker Desktop. При первом запуске собирается образ кросс-компиляции Linux, что требует доступа к сети.

Артефакты записываются в новый каталог внутри `bin/releases/`: ZIP для macOS / Windows, tar.gz для Linux, а также `SHA256SUMS`, создаваемый при успешном завершении всех шагов. Команда ничего не загружает автоматически и не создаёт DMG, NSIS, deb или rpm.

В репозитории также есть рабочий процесс GitHub Actions Release, который собирает шесть целей по тегу версии и объединяет файлы проверки; проверка на реальных runner ещё не выполнена.

### Соглашение о коммитах

Сообщения коммитов следуют Conventional Commits (`<type>(<scope>): <subject>`), проверяются commitlint и генерируются через czg:

```sh
npm install        # Первый раз: установка czg / commitlint / husky и подключение хука commit-msg
npm run commit     # Интерактивная генерация сообщения коммита
```

- **type**: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`, `wip`, `workflow`, `types`, `release`.
- **scope**: имена каталогов `internal/*` и `frontend/src/features/*` автоматически становятся доступными scope, дополнительно доступны `project`, `deps`, `build`, `ci`, `release`, `docs`, `scripts`, `i18n`, `ui`, `other`; scope можно опустить.
- **header**: не более 108 символов, subject не может быть пустым; несоответствующее сообщение отклоняется.

Подробные правила — в `docs/development/commit-convention.md` (этот каталог сохраняется только во внутреннем репозитории).

## Технологии и структура

| Часть                             | Технологии                                                   |
| --------------------------------- | ------------------------------------------------------------ |
| Настольный контейнер              | Wails v3.1.0, Go                                             |
| Фронтенд                          | Vue 3, TypeScript, Vite, Tailwind CSS, Reka UI               |
| Терминал и удалённый рабочий стол | xterm.js, noVNC, helper FreeRDP                              |
| Редактор                          | CodeMirror, Monaco Editor                                    |
| Хранение и шифрование             | SQLite, AES-256-GCM, Argon2id                                |
| Контроль качества                 | Go test / vet, Vitest, Playwright, ESLint, Prettier, vue-tsc |

```text
main.go                  Точка входа приложения и встраивание ресурсов
internal/app/            Фасад Wails, сборка зависимостей, окно и мост к среде выполнения
internal/                Хосты, сессии, терминал, SFTP, AI и другие функции и инфраструктура
frontend/src/app/        Оболочка приложения и точка входа окон
frontend/src/features/   Страницы, панели и логика состояния по функциям
frontend/src/services/   Шлюзы фронтенда и обёртки служб среды выполнения
frontend/src/components/ Общие элементы управления, вёрстка, диалоги и компоненты рабочей области
frontend/src/locales/    Тексты интерфейса на семи языках
frontend/bindings/       Сгенерированные привязки Wails для TypeScript
build/                   Конфигурация сборки по платформам и скрипты публикации
tools/                   Исходники helper для RDP, локальные тестовые фикстуры OTP
Taskfile.yml             Точки входа задач разработки, проверки и сборки
```

Подробнее о назначении каталогов — в [`internal/README.md`](internal/README.md) и [`frontend/README.md`](frontend/README.md).
