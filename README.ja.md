Qterm は **Go、Wails v3、Vue 3、TypeScript** で構築したデスクトップ接続管理ツールで、macOS、Windows、Linux に対応しています。ホスト資産を起点に、マルチタブと分割ペインのワークスペースでサーバーやデバイスに接続し、右側のツールパネルからファイル操作、リソース監視、コンテナ管理、AI アシスタントの利用まで行えます。

インターフェースは简体中文、繁體中文、English、Français、日本語、한국어、Русский の 7 言語に対応しています。

## 機能概要

### ホストと接続

- **統合アセットライブラリ**：ホストと入れ子になったグループを管理し、検索、タグ、メモ、カスタムアイコンと色、サイドバーと全画面のアセットビューに対応します。
- **複数の接続方式**：SSH、Telnet、シリアル、RDP、VNC に対応し、ローカルシェルも開けます。
- **SSH 認証**：パスワード、秘密鍵、SSH Agent、対話型認証、さらに OTP エントリを紐づけた二要素認証の設定に対応します。
- **複雑なネットワーク経路**：SSH 踏み台チェーン、SOCKS5 / HTTP プロキシ。プロキシ設定は再利用でき、RDP と VNC でも踏み台やプロキシ経路を設定できます。
- **接続オプション**：プロトコルごとにターミナル、エンコーディング、キープアライブ、ログイン後のコマンド、SFTP、リモートデスクトップのパラメーターを設定できます。

### ターミナルワークスペース

- マルチセッションのタブ、タブのロックと名前変更、ドラッグによる並べ替え、分割ペイン、セッションウィンドウの切り離しと復帰。
- ターミナル内検索、正規表現で設定できるキーワード強調、コマンド履歴、補完、グループ化したクイックコマンド。
- 設定可能な複数行貼り付けの確認、一括コマンド、右クリックの動作、フォント、カーソル、スクロールバッファー、描画方式。
- セッション履歴とメモ、ターミナル録画、再生、エクスポート。
- ライト / ダークテーマ、ターミナルの配色、背景画像、インターフェースの拡大縮小。

### ファイルと運用

- **SFTP**：ローカルとリモートのディレクトリ閲覧、アップロードとダウンロード、ドラッグ＆ドロップ転送、転送キュー、進捗とキャンセル、上書き確認、ディレクトリ追従。
- **リモートテキスト編集**：内蔵エディターでリモートファイルを開いて編集し、保存時にファイル変更の競合を処理します。
- **ポート転送**：ローカル転送、リモート転送、動的 SOCKS 転送に対応し、グループと稼働状態を管理できます。
- **リソース監視**：CPU、メモリ、ディスク、ネットワークなどの指標と履歴グラフを表示します。利用できる指標はリモート環境によって異なります。
- **プロセスとサービス**：プロセスを表示し、対応システムではサービスを管理してログを確認できます。
- **Docker**：現在の SSH セッション経由でリモートのコンテナ、イメージ、ボリューム、ネットワークを管理し、リソースの詳細とコンテナログを表示します。
- **認証ツール**：TOTP / HOTP エントリを管理し、`otpauth://` や QR コードから取り込み、ワンタイムコードの表示、コピー、QR コード表示を行えます。

### AI アシスタント

ワークスペース内でストリーミング対話を行い、選択したターミナル、ホスト、その他のコンテキストを踏まえて問題を分析し、Agent ツールによるタスク実行を支援します。

- 複数のモデルプロバイダー、サービスアドレス、モデル、API Key を設定でき、接続プレビューに対応します。
- OpenAI Chat Completions、OpenAI Responses、Anthropic Messages のプロトコル形式に対応します。互換サービスの実際の機能はその実装に依存します。
- セッション履歴、Markdown / コード / 数式の表示、コマンド承認、Agent の動作設定に対応します。
- Agent のコマンドはローカルの安全ポリシーと承認設定に従って実行されます。ネイティブなツール呼び出しは OpenAI Chat Completions と Anthropic に対応し、Responses は互換のフォールバックを使用します。

AI を使用する前に、モデルサービスをご自身で設定してください。コンテキストに含めた内容は設定したサービスへ送信されるため、実際のデータ範囲に応じてコンテキストを選択してください。

## 画面と操作の入口

| 画面 / 領域                    | できること                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| アセットライブラリとサイドバー | ホストの検索と整理、グループ管理、接続の開始、既存設定のインポート                                                                                |
| ホストエディター               | プロトコルごとにアドレス、認証、踏み台 / プロキシ、詳細な接続パラメーターを設定                                                                   |
| セッション作業領域             | ターミナルやリモートデスクトップを使い、タブの切り替え、分割ペイン、ウィンドウの切り離しを行う                                                    |
| 右側のツールパネル             | リソース監視、プロセス、サービス、Docker、SFTP、クイックコマンド、コマンド履歴、ポート転送、認証、テーマ、AI アシスタントを開く                   |
| 設定 → 管理                    | 認証情報、フィンガープリント、プロキシ、ポート転送、クイックコマンド、セッション履歴、ターミナル録画                                              |
| 設定 → 環境設定                | アプリケーション、外観、ターミナル、リモートデスクトップ、キーワード強調、認証情報の候補表示、ショートカット、AI アシスタント、このアプリについて |
| 設定 → このアプリについて      | バージョンと更新の確認、インポート / エクスポートなどの入口                                                                                       |

ツールパネルの内容はセッションの種類と接続状態に応じて表示されます。たとえば Docker には接続済みの SSH セッションとリモート側の Docker 環境が必要です。

## はじめかた

1. アプリを起動し、案内に従ってローカル保管庫を初期化するかロックを解除します。
2. グループとホストを新規作成し、プロトコルを選んで接続情報を入力します。既存クライアントからホストをインポートすることもできます。
3. SSH ホストにはパスワード、秘密鍵、SSH Agent のいずれかを設定します。初回接続時はホストのフィンガープリントを確認して承認してください。
4. ホストセッションを開き、右側から必要なツールを選びます。AI を使う場合は、先に「設定 → AI アシスタント」でモデルサービスを設定します。
5. 設定で外観、ターミナル、ショートカット、録画、ファイル転送の環境設定を調整します。

### 設定の移行

OpenSSH 設定、PuTTY、Xshell、Termius、SecureCRT、MobaXterm、WindTerm、FinalShell、Electerm、JSON セッションファイルなどのインポート入口を用意し、Qterm リソースバックアップのインポートとエクスポートにも対応します。

インポート時はまずスキャンしてプレビューし、必要な項目を選択します。移行できるプロトコル、認証情報、詳細オプションはインポート元によって異なり、元のクライアント設定の完全なコピーとはみなせません。マスターパスワードやシステムの認証情報へのアクセスに追加の入力が必要な場合もあります。

### ローカルデータと認証情報

ホスト、グループ、履歴などのデータはローカルの SQLite に保存し、秘密情報は暗号化された保管庫で管理します。保管庫は AES-256-GCM を使用し、マスターパスワードの保護には Argon2id による派生を用います。鍵の調整と復元パッケージの入口も用意しています。SSH の初回接続ではホスト鍵の確認が必要で、信頼したフィンガープリントは設定から管理できます。

## プラットフォームと利用範囲

| プラットフォーム | 配布ターゲット        | 実行時の依存関係 / 注意事項                                                                               |
| ---------------- | --------------------- | --------------------------------------------------------------------------------------------------------- |
| macOS            | Apple Silicon / Intel | システムの WebView を使用します。ローカルのポータブルパッケージは一時署名で、正式な署名と公証は未完了です |
| Windows          | amd64 / arm64         | WebView2 Runtime が必要です                                                                               |
| Linux            | amd64 / arm64         | ビルドターゲットに一致する GTK / WebKit のランタイムライブラリが必要です                                  |

- **RDP は追加の helper に依存**：FreeRDP ベースの helper とその動的ライブラリを使用します。6 プラットフォームのローカルパッケージ入口は、macOS helper がターゲットアーキテクチャと一致する場合にのみ同梱します。Windows / Linux には自動同梱されません。対応する helper がない場合は RDP をそのまま利用できません。
- **リモートツールは環境に依存**：SFTP はサーバー側のサブシステムが必要で、Docker はリモートの CLI と権限が必要です。サービス管理と監視は OS とインストール済みツールによって制限されます。
- **ブラウザープレビューは画面開発専用**：Web 側のインメモリゲートウェイは、ネイティブの SSH、SFTP、リモートデスクトップ、保管庫の機能を代替できません。
- **自動更新は接続済み**：デスクトップ版は GitHub Release を確認し、バックグラウンドでダウンロードして SHA-256 を検証したうえで、ユーザーの確認により再起動してインストールします。準備ができると上部バーに通知します。実際の Release の全経路、Windows / Linux での置き換えと再起動、リリース CI は実機での検証が必要です。
- **クロスプラットフォームの検証は進行中**：ビルドターゲットと既存の実装は、すべての機能が 6 種類の OS / アーキテクチャの組み合わせで検証済みであることを意味しません。

## ローカル開発

### 環境の準備

| ツール                         | 現在のプロジェクト基準                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Go                             | 1.26.0、または `go.mod` と互換性のあるバージョン                                                                           |
| Node.js                        | 22.22.2+ の 22.x、または 24.15.0+ の 24.x。固定した依存関係の engines 要件を満たす必要があります                           |
| npm                            | 固定されたフロントエンド依存関係をインストール                                                                             |
| Wails CLI                      | v3.1.0（Go モジュールのバージョンと一致させる）                                                                            |
| プラットフォームツールチェーン | macOS は Xcode Command Line Tools が必要です。その他のプラットフォームは対応するネイティブビルド依存関係を用意してください |

リポジトリのルートで実行します：

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
npm --prefix frontend ci
wails3 doctor
wails3 task dev
```

Go の実行ファイルディレクトリを `PATH` に追加してください。`wails3 task dev` は `build/config.yml` を使用し、フロントエンドの既定ポートは `9245` です。

フロントエンドのみをプレビューする場合（ブラウザーで `http://127.0.0.1:9245` を開きます。この場合インメモリゲートウェイを使用するため、実際の SSH / SFTP 機能はありません）：

```sh
npm --prefix frontend run dev
```

### チェックとビルド

```sh
# ローカルの完全なチェック：Go のフォーマット、テスト、vet。フロントエンドのフォーマット、lint、型、ユニットテスト、ビルド、E2E
wails3 task check

# 現在のプラットフォームのアプリをビルド
wails3 build

# 現在のプラットフォームのインストール / 配布物を生成
wails3 package
```

完全なチェックにはリポジトリ内のテストファイルと Playwright のブラウザー環境が必要です。コードのみのスナップショットには完全なテストゲートは含まれません。必要に応じて E2E 用のブラウザーをインストールします：

```sh
cd frontend
npx playwright install chromium
```

### 6 プラットフォームのポータブルパッケージ

**macOS** のリポジトリルートで実行します：

```sh
# 計画のみを出力
wails3 task release:all DRY_RUN=true

# 実際にビルド
wails3 task release:all
```

Go、Node.js/npm、Wails CLI、Xcode Command Line Tools、起動済みの Docker Desktop が必要です。初回実行時は Linux 向けクロスコンパイルイメージをビルドするため、ネットワーク接続が必要です。

成果物は `bin/releases/` 配下の新しいディレクトリに出力され、macOS / Windows の ZIP、Linux の tar.gz、すべて成功した場合に生成される `SHA256SUMS` が含まれます。このコマンドは自動アップロードを行わず、DMG、NSIS、deb、rpm も生成しません。

リポジトリには GitHub Actions の Release ワークフローもあり、バージョンタグに応じて 6 種類のターゲットをビルドして検証ファイルをまとめます。ワークフローの実際の runner での検証はまだ完了していません。

### コミット規約

コミットメッセージは Conventional Commits（`<type>(<scope>): <subject>`）を使用し、commitlint で検証し、czg で生成します：

```sh
npm install        # 初回：czg / commitlint / husky をインストールし、commit-msg フックを設定
npm run commit     # コミットメッセージを対話的に生成
```

- **type**：`feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`、`revert`、`wip`、`workflow`、`types`、`release`。
- **scope**：`internal/*` と `frontend/src/features/*` のディレクトリ名がそのまま選択可能な scope になり、さらに `project`、`deps`、`build`、`ci`、`release`、`docs`、`scripts`、`i18n`、`ui`、`other` があります。省略も可能です。
- **header は最大 108 文字**、subject は空にできません。ルールを満たさないコミットは拒否されます。

ルールの詳細は `docs/development/commit-convention.md` を参照してください（このディレクトリは内部リポジトリのみに保持されます）。
